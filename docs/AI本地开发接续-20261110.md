### 后端有改动，需要重启

1. 用 lsof/ps 和进程 cwd 确认 18080 是自己负责的知项 API。当前 API 直接使用 target 下的 JAR，**先正常停止该 API 再重打包**，避免覆盖运行中的懒加载 JAR。不要照抄历史 PID，先现场核对。
2. 在后端工程执行：

```sh
mvn -s scripts/maven-settings.xml -B -ntp package
```

3. 在交接包目录运行检查（后端仓库同一脚本在 scripts/start-local-api.py）；确认18080空闲后启动：

```sh
python3 start-local-api.py check
python3 start-local-api.py start
```

此脚本读取现有本机配置和持久HMAC，覆盖正确隔离数据库/vhost与三个Vite Origin，关闭真实短信和模型；先对原隔离库执行增量迁移，再从独立 JAR 快照启动API。不创建数据库、不重置账号、不启用生产供应商。前台运行，Ctrl+C 仅停止自己启动的 API。日志在隔离 secrets 目录的 `local-dev-handoff/api.log`。

脚本本轮只验证了语法、配置检查以及“18080已占用时拒绝重复启动”，没有为测试脚本重启当前 API。启动后必须实际检查 readiness，不能仅凭“已创建进程”认定成功。

4. 需要扫描、通知、导出等异步任务时，在后端另一个终端启动专用worker：

```sh
python3 scripts/start-ui-worker.py
```

该脚本使用相同隔离库、同名 vhost 和持久HMAC，默认模型与视频处理关闭。它会准备专用vhost/权限和exchange，检查原worker状态，使用独立JAR快照。启动后检查受保护 `worker.log` 中的成功启动记录及真实任务状态，不要输出整份可能含业务数据的日志。本轮没有替接手助手启动它。
